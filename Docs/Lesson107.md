# Практическая 10.7 — движение в заданной зоне

## Запуск

Откройте проект в Unreal Engine 5.8.3 с загруженными Git LFS ресурсами. Стартовая карта — `/Game/StealthShooter/Maps/L_BoundedPatrol`. Нажмите Play: обзорная камера показывает двух автономных акторов, прямоугольник патрулирования и три препятствия класса StaticMeshActor. Предыдущие практические открываются на своих прежних картах.

## Требования и реализация

| Требование | Реализация |
| --- | --- |
| ThirdPerson Template | Сохранены персонаж, GameMode и ресурсы исходного шаблона. Демонстрация размещена на отдельной карте. |
| Скорость Speed | Редактируемое в экземпляре свойство в см/с. `ConfigureMovement` передаёт его в `CharacterMovement.MaxWalkSpeed`. На сцене заданы 180 и 280 см/с. Изменение Speed применяется каждые 0,2 с. |
| MinX / MaxX / MinY / MaxY | Мировые границы центра актора по XY. По умолчанию X от −900 до 900, Y от −800 до 800. Разметка на демонстрационной карте соответствует этим значениям. |
| Случайная точка внутри зоны | Встроенный `GetRandomReachablePointInRadius` выбирает достижимую точку NavMesh. `ContainsPoint` отбрасывает точки вне прямоугольника; от края оставлено 65 см для капсулы и плавного поворота. |
| Выход за границу | `RefreshPatrol` обнаруживает выход, один раз заменяет текущую цель и направляет актора обратно. `bReturning` предотвращает непрерывный перезапуск активного маршрута. |
| Обход Static Mesh Actor | NavMesh учитывает блокирующие меши; PathFollowing направляет CharacterMovement вокруг них. Капсула радиусом 34 см дополнительно обеспечивает физическое блокирование. |
| Только MovementComponent и AIMoveTo | Единственный запрос перемещения — стандартная нода `AIMoveTo` в `MoveToTarget`. Нет SetActorLocation, AddActorWorldOffset, ручного Tick-перемещения или физической симуляции в игровой логике. Поворот выполняет CharacterMovement с OrientRotationToMovement. |
| Оформление | `Movement/Patrol/BP_BoundedPatrol`, карта в Maps, PascalCase, булевы с b, категории Configuration / State / Diagnostics, короткие функции, Return и комментарии. |

`SampleDestination` — непустая по исполнению функция-обёртка, которая возвращает вместе Candidate и bFound. Это сохраняет согласованность выходов случайного pure-запроса и предотвращает повторную генерацию точки при последующих проверках. При неудачном выборе новая попытка происходит на следующем такте таймера. Успех и неуспех AIMoveTo планируют следующую цель без рекурсивного вызова. EndPlay очищает таймер.

`RequestDestination` принимает корректную точку назначения; `RestartPatrol` сбрасывает планирование после внешнего изменения позиции. Эти функции используются также для воспроизводимых проверок. Перемещения тестовой постановки выполняются только проверяющим сценарием, не игровым Blueprint.

## Настройка

Задавайте MinX < MaxX и MinY < MaxY, оставляя свободную проходимую область размером больше 130 см по каждой оси. NavMeshBoundsVolume должен покрывать всю зону, препятствия и доступную область возврата снаружи. Все пути должны иметь достаточную ширину для капсулы. Отрицательный Speed приравнивается к нулю. Если достижимой цели нет, актор ждёт и повторяет выбор без телепортации.

Разметка — декоративные меши без коллизии, а не невидимые стены. При изменении границ в экземпляре обновите разметку вручную или ориентируйтесь на значения свойств. Обзорная камера служит демонстрации; исходные ThirdPerson ассеты не изменены.

## Проверки

`PatrolValidation107.json`: 43 проверки, 0 ошибок; 711 измерений в настоящем Play. Проверены повторные случайные маршруты, маршрут слева направо вокруг центрального блока, отдельный возврат после пересечения MinX, MaxX, MinY, MaxY, смена Speed на 100 и 360, нулевая и отрицательная скорость. На измеренных маршрутах капсулы не пересекали три препятствия, актор оставался на полу и не превышал заданную скорость. Blueprint компилируется без ошибок и предупреждений; проверено наличие одной ноды AIMoveTo и отсутствие ручных нод перемещения.

Тестовые сценарии находятся в `Tools/validate_bounded_patrol.py`; они выполняются редактором, не требуются для обычного запуска и не включаются в игровую логику. Дополнительные отчёты регрессии проверяют старые карты взаимодействия и UMG.
